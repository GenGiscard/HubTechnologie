Le binaire,
le langage des machines

Ton téléphone, ta console, l’ordinateur de la salle de techno : aucun ne comprend nos chiffres. Tous ne connaissent que deux signes, 0 et 1. Ce cours explique comment, à partir de ces deux signes seulement, une machine représente des nombres, du texte, des couleurs et même la position d’un capteur.

1Pourquoi seulement des 0 et des 1 ?

À l’intérieur d’un circuit, il n’y a pas de nuances.

Dans un circuit électronique, une information se transporte par le courant. Or un interrupteur n’a que deux états possibles : le courant passe, ou il ne passe pas. On note ces deux états 1 et 0.

C’est un choix de fiabilité. Distinguer deux états est facile, même si la tension varie un peu ou si le composant vieillit. Distinguer dix niveaux différents serait bien plus fragile.

Un bit (de l’anglais binary digit) est la plus petite information possible : un 0 ou un 1. Un octet est un groupe de 8 bits. C’est l’unité de base de la mémoire, celle qui donne les kilooctets, mégaoctets et gigaoctets.

2Le binaire naturel : une histoire de poids

Chaque bit vaut quelque chose, selon sa place.

Dans un octet, chaque bit porte un poids. En partant de la droite, les poids doublent à chaque fois : 1, 2, 4, 8, 16, 32, 64, 128. Pour lire un nombre binaire, il suffit d’additionner les poids des bits allumés.

Essaie toi-même : allume et éteins les bits, et observe la même information écrite dans plusieurs codes à la fois.

Avec 8 bits, on peut écrire 256 nombres différents, de 0 à 255. Chaque bit ajouté double le nombre de possibilités.

3L’hexadécimal : écrire plus court

Huit bits, c’est long. Deux symboles suffisent.

Écrire 11010110 est pénible et source d’erreurs. On regroupe alors les bits par paquets de 4. Chaque paquet vaut de 0 à 15, et on lui donne un seul symbole : les chiffres 0 à 9, puis les lettres A, B, C, D, E et F pour 10 à 15.

Décimal01234567 89101112131415
Hexa01234567 89ABCDEF
Un octet s’écrit toujours avec exactement deux symboles hexadécimaux. L’hexadécimal ne change rien à l’information : c’est la même chose, écrite plus court.

4Le code ASCII : coder du texte

Une lettre est un nombre, donc un octet.

Une machine ne sait pas ce qu’est une lettre. On a donc fixé une table qui associe un nombre à chaque caractère : c’est le code ASCII. La lettre A vaut 65, B vaut 66, et ainsi de suite. Les minuscules commencent à 97, les chiffres à 48.

Un texte n’est rien d’autre qu’une longue suite d’octets. Ouvrir un fichier texte, c’est lire ces octets et afficher les caractères correspondants.

5Les couleurs : trois octets par pixel

Rouge, vert, bleu — et tout le reste en découle.

Un pixel d’écran est fait de trois lumières minuscules : une rouge, une verte et une bleue. Pour chacune, on code une dose de 0 à 255, donc un octet. Un pixel occupe ainsi trois octets, qu’on écrit souvent en hexadécimal sous la forme #RRVVBB.

Trois octets donnent 256 × 256 × 256, soit plus de 16 millions de couleurs. #FF0000 est un rouge pur, #000000 le noir, #FFFFFF le blanc.

6Deux codes pour des besoins particuliers

Le binaire naturel n’est pas toujours le plus pratique.

Le DCB (décimal codé binaire) code chaque chiffre séparément sur 4 bits, au lieu de coder le nombre entier. Le nombre 27 devient 0010 0111 : le 2, puis le 7. C’est moins compact, mais un afficheur d’horloge ou de calculatrice peut piloter directement chaque chiffre sans calcul.

Le code Gray, ou binaire réfléchi, est construit pour qu’un seul bit change d’un nombre au suivant. On l’utilise dans les capteurs de position : si plusieurs bits changeaient en même temps, une lecture prise au mauvais instant donnerait une position complètement fausse.

On ne choisit pas un code au hasard : chacun répond à un besoin. Compact pour le calcul, lisible pour l’affichage, sûr pour la mesure.
